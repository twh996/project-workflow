# AI 协作开发工作流（project-workflow）

> 让 AI 开发项目时不再"越做越傻"。用项目文件代替对话记忆，一个会话只做一个功能，自动维护架构文档与任务看板。

一个 WorkBuddy 技能。装好后，你只需要说「开工」「做登录功能」「收工」，它会自动把项目文档和进度维护好。

---

## 你遇到的是这个问题吗

用 AI 做项目的人几乎都会撞上同一堵墙：

- 一个对话框里做到第三、第四个功能，AI 开始忘事、前后矛盾、重复问已经回答过的问题
- 上下文一满只能重开会话，但 AI 完全失忆，你得从头交代一遍
- 于是你不敢碰复杂项目，永远停在"玩具"阶段

根因不是模型不行，是**记忆存错了地方**。对话窗口是工作台，不是仓库。

## 它做什么

把记忆从对话里搬到项目文件里，让每个新会话的 AI 都能在一分钟内接上进度。

| 文件 | 作用 | 更新频率 |
|---|---|---|
| `ARCHITECTURE.md` | 技术选型、目录结构、代码约定、禁止事项、关键数据结构 | 低 |
| `TASKS.md` | 任务看板：进行中 / 待办 / 已完成 / 下一步 | 每次会话 |
| `README.md` | 怎么运行、怎么验证 | 极低 |
| `.gitignore` | 排除缓存、临时文件、密钥 | 极低 |

## 安装

把整个 `project-workflow` 目录放到技能目录下：

```
# 用户级（所有项目可用）
~/.workbuddy-ai/skills/project-workflow/

# 项目级（仅当前项目，适合团队共享）
<项目根目录>/.workbuddy-ai/skills/project-workflow/
```

Windows 下用户级路径为 `C:\Users\<用户名>\.workbuddy-ai\skills\project-workflow\`。

## 使用

不用背提示词，说人话就行：

| 你说 | 它做什么 |
|---|---|
| 「开工」「开始一个新项目」 | 先问你 3-5 个关键问题 → 生成四份文件 → 建目录骨架 → 初始化 git |
| 「做登录功能」 | 读文档并复述当前进度 → 只做这一个功能 → 主动收工存档 |
| 「收工」 | 更新 `TASKS.md` → 把踩的坑提炼成约束 → `git status` 预检 → 提交 |
| 「上下文快满了」 | 立即存档并提示你开新会话 |
| 改 bug、小调整 | 直接做，不走流程 |

## 几个不显眼但关键的设定

- **踩坑的归宿是「约束」，不是「日志」**。能变成"以后必须用 X 代替 Y"的，写进 `ARCHITECTURE.md` 的禁止事项；提炼不出来的直接删。躺在日志里的坑，AI 下次照样踩。
- **已完成项只保留最近 5 条**。防止 `TASKS.md` 一路长胖，变成新的上下文负担。
- **`ARCHITECTURE.md` 只保留当前有效的约定**。过期的直接删，否则 AI 会照着废弃方案写代码。
- **模板强制读取**。四份文件由 `templates/` 生成而非现编，结构固定，你永远知道该去哪个文件找什么。
- **轻量任务直接放行**。改动 ≤2 个文件且不新增文件，不走流程——避免"为了流程而流程"。

## 适合 / 不适合

**适合**：用 AI 从零开发的中小型项目；功能需要逐个迭代；你本人不写代码、由 AI 承担实现。

**不适合**：一次性脚本、纯问答、临时实验；大型多人协作项目（需要更重的工程规范）。

## 目录结构

```
project-workflow/
├── SKILL.md                     场景分流（A 开工 / B 开发 / C 收工 / D 急救）+ 硬规则
└── templates/
    ├── ARCHITECTURE.md          架构说明骨架
    ├── TASKS.md                 任务看板骨架
    ├── README.md                项目说明骨架
    └── .gitignore               通用忽略规则
```
